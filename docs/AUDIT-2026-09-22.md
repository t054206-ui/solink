# Solink — frontend QA and audit, 2026-09-22 (Session 8)

Scope: every page route (78), the API routes, navigation, protection, honesty
labelling, responsiveness at phone width, console and build. Method: the
structure review read every route against `src/lib/navigation.ts` and
`src/proxy.ts`; a demo-mode build served all 78 routes to an automated
smoke test; ten key pages were loaded at 375 px and measured for horizontal
overflow, broken images and console errors; type check, lint, `npm audit`
and the production build ran. Three planned deep-dive reviews (honesty and
copy, security and data layer, code quality) were cut short by the
account's spending limit and are listed below as not fully covered.

## Results of the automated checks

- All 78 routes return 200 in demo mode (`/consent` redirects to sign-in, as designed).
- Every internal link in `src` resolves to an existing page; the 7 SOON links are non-clickable by design.
- Phone width (375 px): no horizontal overflow, no broken images, no console errors on dashboard, marketplace, compare, designer, calculator, passport, monitoring, admin products, profile, analysis.
- `npx tsc --noEmit` clean, `npx eslint src` clean, `npm audit --omit=dev` 0 vulnerabilities, production build clean.
- Live site: public routes 200, protected routes redirect to `/login`, HSTS present.

## Fixed in this pass

1. `/notifications` was reachable signed-out (missing from `PROTECTED_PREFIXES`); the dead `/settings` prefix removed. `src/proxy.ts`.
2. No security headers beyond HSTS: added `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`. `next.config.ts`. No CSP yet (see decisions).
3. Solar Passport detail page had no title (browser tab showed the site default). `src/app/(app)/passport/[systemId]/page.tsx`.
4. Public and sign-in areas had no error boundary; the app boundary showed the raw technical message. Added `(marketing)/error.tsx`, `(auth)/error.tsx`; `(app)/error.tsx` now shows a plain sentence and a reference code.
5. Two copies of the verification label map (admin and marketplace) could drift; the admin now reuses the marketplace map. `admin-helpers.ts`.
6. Admin in-page menu used different names from the sidebar for the same pages (Alerts / AI Alerts, Platform Settings / Settings, …); aligned to the sidebar. `admin-sections.ts`.
7. Footer link "Integration status" led every visitor to an admin-only page; label now says it is for administrators. `Footer.tsx`.

## Flags for the owner's decision (nothing applied)

1. **Intro film on every full page load** (`INTRO_FREQUENCY = "always"`, root layout): ~20 s before every reload, including admin and sign-in. Recommend `"session"`. Your word.
2. **Three copies of the admin menu**: app sidebar, the `AdminNav` column on every admin page, and the "Admin sections" card on `/admin`. Recommend keeping the sidebar and the in-page column (it is the only admin navigation when the sidebar is closed on phones) and dropping the card.
3. **Provider double navigation**: `ProviderNav` repeats three sidebar items; the manufacturer layout deliberately does not do this. Recommend removing `ProviderNav`.
4. **Half the provider sidebar is SOON** (Requests, Systems, Reports, Settings). Either build the four pages (Requests could be the case queue filtered) or hide the SOON items until they exist.
5. **Empty-state shells**: `/manufacturer/orders`, `/manufacturer/settings`, `/monitoring/panels`, `/monitoring/nearby`. They explain honestly what is missing; keep or hide is a product call.
6. **Arabic coverage**: only marketing, auth and legal pages read the dictionary; the 38 homeowner pages, provider, manufacturer and admin are English-only. Large piece of work; decide the order.
7. **Content-Security-Policy**: not set. Needs an allow-list for Supabase, Google Maps, the vendored three.js and inline bootstrap, plus a test pass.
8. **Leaked-password protection** is off in Supabase Auth (dashboard toggle).
9. **`/manufacturer` redirect page** and the duplicate `/profile` CTA on the landing page: harmless; remove only if you want fewer files.
10. **Em dashes**: 171 occurrences, almost all the "—" empty-value placeholder in tables, not prose. The page title "Solink — The complete solar-energy ecosystem" is the one prose case. Decide whether the design rule covers placeholders.
